記憶與情境汙染ASI06 · Memory & Context Poisoning

騙代理一次，只影響這一次；改掉它的「記憶」，它就會一直錯下去，還會傳染給其他代理。

代理靠記憶延續工作：對話紀錄、記憶工具、摘要、向量資料庫（RAG）。攻擊者只要把惡意或誤導的資料塞進這些地方，代理日後的推理、規劃和工具使用就會一直被帶偏，甚至幫忙外洩資料。而且這種汙染會跨越工作階段持續存在。

LLM01 提示注入+LLM04 資料投毒+LLM08 向量弱點=ASI06 持久的記憶汙染
✍️ 寫進去從對話、上傳、API、其他代理寫入假資料

    04 · 劃清界線

    四個容易混淆的鄰居

    OWASP 說明：ASI06 的「情境」包含代理保存、檢索或重用的任何資訊（摘要、嵌入向量、RAG 資料庫），但不包含一次性的輸入提示（那是 LLM01）。它也和 ASI01（直接操控目標）、ASI08（汙染之後的連鎖失效）不同。不過記憶汙染常常會「導致」目標劫持。讀完卡片，幫下面五個案例分類。

      07 · 看不見的鄰居

      只因為「意思很像」，就讀到別家公司的機密

      OWASP 情境 5：多個租戶共用一個向量資料庫，而 namespace 過濾又設得太鬆。攻擊者在自己的租戶植入「幾乎一模一樣」的內容，再用相似的問題查詢；因為餘弦相似度很高，另一個租戶的敏感段落就被拉進檢索結果。依序按兩個步驟，再試試打開防護。

      08 · 記憶衛生

      讓沒驗證過的記憶，自己慢慢「褪色」

      OWASP 建議：每筆記憶都有來源與信任分數；未驗證的記憶隨時間衰減並到期；禁止代理把「自己的輸出」自動回灌進可信記憶（避免自我強化的「自舉汙染」）；高影響的記憶要同時具備「來源分數」和「人工驗證標記」才能被使用。拖動天數，切換開關看看差別。
